# core-must —— DDD 精髓原则层条款（DDD-01~15）

> 载体无关。Java 新项目另叠 assets/payment/java-backend-guardrails 的代码级条款。每条含「判据」供评审勾对与测试覆盖。

## 依赖与边界

- **DDD-01 单向依赖**：领域层 MUST NOT import 技术设施（DB/MQ/缓存/HTTP/框架）。判据：领域包依赖图零技术设施节点（架构测试或 import 检查）。
- **DDD-02 接口定义在调用侧**：跨层能力（持久化、外呼、MQ、锁、幂等、ID）MUST 由使用方声明接口，技术侧只做实现。判据：接口包位置在调用方模块/层，实现在技术层。
- **DDD-03 契约极薄**：对外契约（API jar/Schema）MUST NOT 含枚举、返回码常量、异常类、内部模式字段；模式差异用行为字段替代。判据：契约包扫描无 enum/常量类；内部模式重构上游零改动。
- **DDD-04 入口无脑转发**：Consumer/Controller/Scheduler 入口只做「接收→转换→调应用服务」，MUST NOT 查库/调外部/直改领域模型/绕过应用服务；入口 MUST 套统一模板（校验→执行→异常收口）。判据：入口类无 Repository/外呼依赖；转换器与入口同包。

## 编排与规则

- **DDD-05 编排与规则分离**：用例编排层（AppService）独占事务、幂等、流程与 Gateway 调用；规则层（DomainService/聚合根）零 I/O、零框架感知、出入参为领域类型。判据：规则层依赖图零基础设施；规则函数可独立穷举测试。
- **DDD-06 状态唯一推进**：状态流转 MUST 收敛为单一转移入口 + 集中转换表（禁散落 if-else/setStatus/语义包装方法），表未注册的转移 MUST 抛异常，终态 MUST 拦截。判据：全仓状态推进调用点唯一；转换表一张表可全审。
- **DDD-07 三路径分离**：创建（初始态）/ 业务推进（查表+校验+事件）/ 重建（旁路，不触发业务校验与状态机）MUST 严格分离。判据：仓储重建路径不经过 transferStatusByEvent、不触发 validate。
- **DDD-08 事件后置派发**：领域事件先内存收集，事务提交后排空发送；发不发、发什么收敛为一张映射表。判据：事务内无外发调用（MQ/通知）；事件路由表集中可审。

## 类型与资损防御

- **DDD-09 类型即契约**：有业务含义、不可变、自校验的值（金额等）MUST 值对象化（成对携带币种、显式舍入），MUST NOT 裸标量直传。判据：金额字段类型为值对象；跨币种操作编译期/构造期拒绝。纯标识符不强建值对象（防过度设计）。
- **DDD-10 落库先于外发**：外呼外部系统前 MUST 已有已提交单据；渠道结果 MUST 分两轴（接口 success × 业务结果），未知≠失败；幂等命中 MUST 报重复，不回捞旧单冒充本次结果。判据：外呼点前存在已提交落库动作；两轴字段独立存在。

## 事务与并发

- **DDD-11 事务边界在编排层**：事务 MUST 由用例编排层以显式模板持有（禁隐式注解事务）；事务内 MUST NOT 调外部系统/发 MQ；技术异常 MUST 在端口实现内翻译为业务异常，不得穿越层边界。判据：全仓无注解事务；事务作用域内无外呼；框架异常类型不出现于编排层以上。
- **DDD-12 一锁二判三更新**：并发可变数据更新 MUST 先锁（select for update 或等价）→ 再判（状态/余额）→ 后带版本更新；可变业务表 MUST 带 version 列，更新 WHERE version=?，0 行受影响按版本冲突处理。判据：更新 SQL 带 version 条件；冲突路径有显式错误码。

## 持久化隔离

- **DDD-13 持久化对象贫血隔离**：持久化对象（PO/记录）MUST 只存在于技术层、零业务方法；领域对象与 PO 的转换 MUST 集中于技术层转换器（禁散落 get/set 手写）；转换 MUST 显式声明未映射即失败（编译期或测试期红）。判据：PO 类型不出现在领域/编排层；转换器单点收口。

## 方法论

- **DDD-14 规则资产化三层闭环**：团队级约束 MUST 同时以三种形态存在并互相编号引用——可勾对条款（Agent/评审执行）、机器强制（架构测试/lint/CI 门禁）、why 文档（人理解传播）。判据：每条硬条款有对应门禁或测试用例；门禁有效性以用例数为准，不以注释声明为准。
- **DDD-15 增量渐进**：旧项目/存量代码 MUST NOT 大爆炸重构——新代码先行遵循，存量按「改哪块收敛哪块」渐进，每步独立可交付可回滚。判据：重构 diff 单一痛点单一迭代，无跨痛点混合提交。
